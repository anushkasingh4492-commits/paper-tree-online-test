# Generator contract - v1.4.0

1. Keep each ID, stem, assumptions, options and figure links together. Render the assumptions with the question. Explicit stem conditions take precedence.
2. Render all figure links relative to the extracted release directory. Use figure_required to distinguish required figures from optional context. All figures remain linked; alt text provides accessible context or readings. A required-figure count is metadata, not a claim that every dependency has been independently certified.
3. Student delivery must omit keys, explanations, provenance, authoring data and numerical answer values. If an importer shuffles options, remap the key and any option-letter references.
4. For numerical delivery use only a non-null numerical_variant, its question, the parent assumptions and figures. Grade against answer_integer in the explicitly requested scaled units. Rounding is nearest integer, exact halves away from zero.
5. Select at most one item per concept_family, including MCQ/numerical presentations of the same item. Aliases protect Kepler, gas-pressure/RMS variants, basic moments of inertia, basic gate truth tables, rod magnetic drag and related experimental/calibration content. Some groups deliberately cap broader related tasks conservatively.
6. The practice blueprint is 20 MCQs and 5 numerical answers, +4/-1/0 for both, maximum 100 marks. Total levels are 8 Easy / 11 Medium / 6 Difficult; classes alternate 12/13 by seed; a unit contributes at most three questions; MCQ keys are five each A/B/C/D.
7. Numerical selection now uses 1 Easy / 2 Medium / 2 Difficult items. These difficulty, class and unit quotas are editorial choices, not NTA rules. Different seeds need not produce wholly disjoint papers.
8. Preserve Unicode, scientific notation and nested CSV JSON fields. Do not interpret a numerical alternative as a new independent question.

No NTA endorsement, external expert certification, student-calibrated difficulty or future syllabus monitoring is implied by validation_status.

The v1.4.0 rotation-energy guard includes all members of both former 0442/0446 families, and preserves all earlier guards.
